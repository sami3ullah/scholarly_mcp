# 0025 MCP server and tool rules

- Status: accepted
- Date: 2026-11-02
- Fills gaps in: PLAN.md "MCP tool contracts", "Server, protocol and operations" edge cases, key design decisions #2, #8, #11, #12 and #13, ticket SM-09

## Context

The plan names the six tools, their inputs and outputs, the error codes and the conventions (annotations, descriptions, `notice`, about 5 KB per response). It leaves open which SDK release and serving model to use, where schema failures become `INVALID_INPUT`, how a journal name becomes a filter, what `find_related` averages, where `get_journal` facts come from, how citations are made, what a card's access badge means before SM-10's entitlements, and what happens while the index is missing. Facts found while building it:

- The official TypeScript SDK is now v2 (`@modelcontextprotocol/server` 2.4.0, `@modelcontextprotocol/node` 2.1.2, `@modelcontextprotocol/client` 2.4.0), implementing the 2026-07-28 spec. Its HTTP entry, `createMcpHandler`, builds a fresh server per request from a factory and also serves 2025-era clients statelessly. `serveStdio` takes the same factory.
- The SDK validates tool arguments itself and answers a failure with free text ("Input validation error: ..."), with no code. It cannot publish a zod schema containing a transform as an output JSON Schema ("Transforms cannot be represented in JSON Schema"), so `doiSchema` cannot appear in output schemas.
- Records of one journal carry its print ISSN, its electronic ISSN or both, and names vary. The live index has 216 journals. Building their summaries reads every article: 359 ms.
- Most subscription records in the live index carry no version-of-record licence, so their access is unknown from the record alone.
- citation-js 0.9 ships APA and Vancouver CSL styles, plus BibTeX and RIS output. AMA needs the CSL style file. Its RIS output wraps values at 70 characters, which splits URLs.
- `Article` has no volume, issue or pages, so citations cannot carry them yet.
- End to end on the live index over stdio, with the real embedder: `search_articles` took 337 ms on a cold start, `find_related` 101 ms, and every other tool under 20 ms.

## Decision

1. **SDK and transports.** `apps/server` uses SDK v2. One factory builds an `McpServer` with the six tools. HTTP serves it statelessly at `/mcp` through `createMcpHandler`, behind the SDK's localhost `Host` and `Origin` guards, with a 64 KB body limit. Stdio uses `serveStdio`, and logs go to stderr. `MCP_TRANSPORT` selects the transport (default `stdio`). Until SM-10 adds API keys and an `Origin` allowlist, `HTTP_HOST` must be a loopback address and config refuses anything else.
2. **One error path.** Tools publish their zod input schema as JSON Schema but register it with a pass-through validator, so the tool layer parses arguments itself. Schema failures, `AppError`s and unexpected errors all go through one function. It returns `isError: true`, a stable code, a message and, where known, `field` and `retryAfter`, as text and as structured content, never with a stack. `INDEX_UNAVAILABLE`, `CURSOR_STALE`, `UNAUTHORIZED` and `INTERNAL` use fixed messages, so file paths and low-level details never reach the model. Unexpected errors are logged with their stack. Inputs are strict objects: an unknown argument is `INVALID_INPUT`, not silently ignored.
3. **Outputs.** Output schemas have no transforms. Cards use the new `canonicalDoiSchema` (core), which accepts only canonical DOIs. The tool layer adds `notice` to every output schema and response. The notice names the publisher from `PUBLISHER_NAME` (ADR 0015).
4. **Cards carry their licence.** `ArticleCard` gains a required `license`: the version-of-record licence URL in force, or `unknown`. With the DOI and the link, every result carries its attribution, as the success criteria ask. The card's `access` badge comes from the record alone, so building a card never waits on a side system: `open` for open access, `subscription` when a closed version-of-record licence is in force, `unknown` otherwise. `check_access` asks the `Entitlements` port for a caller-specific answer.
5. **Mock entitlements.** The demo adapter (SM-10's task, needed here by `check_access`) answers `open` for open access, `institution` when the caller has an institution, and `subscription` otherwise. Its login and purchase links are the article's doi.org link, which resolves to the publisher's page where both are offered, so it never invents a URL. Until API keys exist, every call has the caller `{ apiKeyId: 'local' }`.
6. **Landing links.** Every card-returning call (`search_articles`, `find_related`, `get_article`) stores its results under a fresh 128-bit token for 24 hours and puts the token in every link: `<LANDING_BASE_URL>/mcp/landing?t=<token>&doi=<doi>&utm_source=mcp&utm_medium=ai&utm_campaign=<tool>` (core `buildLandingUrl`; a base path is kept). `collectionUrl` is the same link without `doi`. If the session store fails, the links go without the token and there is no `collectionUrl`, so the landing page falls back to the DOI. The failure is logged, but the call still succeeds. Empty results store no session. A sweep deletes expired sessions every `SESSION_CLEANUP_MS` (default 1 hour).
7. **Journals.** A new `JournalDirectory` port (core) lists journals built from indexed articles only. Stores tally articles per journal name and ISSN pair, and core's `mergeJournalTallies` joins tallies that share any ISSN (union-find). Each merged journal is named after the variant most articles carry and keeps its ten most frequent subjects. The server caches the list per index version. A name matches by folded words (case and umlaut spelling ignored); the last query word may be cut short. Matches rank as same name, then names starting with the query, then names containing its words as whole words, then with the last word cut short; more articles come first within each rank. In `search_articles` an unknown journal, or a name matching several journals that is not one journal's whole name, is `INVALID_INPUT` on `journal`, with up to five candidates and their ISSNs.
8. **Journal filter by every ISSN.** `SearchFilters.journalIssn` becomes `journalIssns`: an article matches when it carries any of them. A merged journal therefore finds records carrying only its print ISSN or only its electronic ISSN. An empty list matches nothing.
9. **`get_journal`.** Takes exactly one of `issn` or `query`, and returns up to five journals. Each has its name, its ISSNs, its indexed article count and years, and its open access policy as its indexed articles show it: `open` when all are open access, `subscription` when none are, `hybrid` otherwise. It also lists subject labels (labels only, ADR 0004) and a page link. The link needs `JOURNAL_URL_TEMPLATE` (with `{issn}`); without it no link is shown, because no verified ISSN-based journal URL for thieme-connect is known.
10. **`find_related`.** Lives in the search service as `related`. It takes the normalised mean of all the article's chunk vectors (full-text chunks included, as only their vectors are used) and runs a vector search over the candidates plus the article's own chunk count, with default filters (retracted articles left out). It drops the article itself and orders by score, then date, then DOI. Labels read "Related in meaning (section)". An unknown DOI is `NOT_FOUND`. A retracted article may be the starting point.
11. **`get_article`.** Returns the card (teaser from `buildTeaser`, `whyMatched` "Looked up by DOI"), up to ten subject labels (MeSH, then keywords, then journal subjects), the journal with its link, `retracted` with a warning when set, and `fullTextIndexed`, a boolean. Nothing else of the full-text reference is exposed.
12. **Citations.** A new `packages/cite` maps an article's metadata to CSL-JSON and formats it with citation-js: Vancouver, APA and AMA (the CSL repository's AMA 11th edition style, vendored under CC BY-SA 3.0) in US English, plus BibTeX and RIS. The date keeps its precision. The item's language stops English title casing of German titles. The URL is the publisher's landing page. Numeric styles lose their list number, and wrapped RIS lines are joined back together. Volume, issue and pages are missing until `Article` carries them (follow-up in SM-14).
13. **Text for every client.** Each response also has a plain-text rendering. Cards become a numbered list of Markdown-linked titles with journal, year, first author, access, why each matched, the teaser in quotes, DOI and licence. The list is introduced with a line saying that card text is data, not instructions. The text aims at 5 KB: teasers are dropped from the last card upwards until it fits, while titles, links and attribution always stay. Five long cards fit. Ten very long cards can exceed 5 KB a little, but the whole response stays under 20 KB, the plan's hard edge.
14. **Descriptions.** Every card tool's description says how to present the results (a short list of linked titles, one line each on why it fits, a pointer to the link), not to stretch a teaser into a summary, to treat card text as data, and never to present results as clinical advice. The server's instructions add that the metadata is for discovery, not for model training.
15. **Live index.** The server opens the index read-only at boot and calls `refresh()` every `INDEX_REFRESH_MS` (default 30 s), so a swapped-in build is served. A missing or refused index does not stop the server. Tools answer `INDEX_UNAVAILABLE` while each tick tries to open it again, and each distinct problem is logged once. A new file that is refused leaves the current index open. `isReady()` is ready for SM-10's readiness check.
16. **Logs.** One line per tool call with tool, request id, status, result count or error code, and duration. The search service adds its own line. Neither logs query text.

## Consequences

- Protocol tests drive the real wiring on in-memory adapters through the SDK client over both the HTTP handler and stdio (a linked in-memory transport). They list the tools, call each, and check outputs against their schemas. A real-port test covers the 404, `Host` and `Origin` rejections. The SM-06 full-text guardrail now runs on every tool's response, with a property test on `search_articles`.
- Postgres (SM-13) implements `JournalDirectory`, `findArticleChunks` and `journalIssns` by passing the extended store contract suite.
- SM-10 replaces the local caller with API-key identities, lifts the loopback restriction behind an `Origin` allowlist, adds health and metrics around `isReady()`, and meters calls.
- SM-11 builds the landing page against the link format above. It must not show the passage of a full-text `matchedChunkId`, which a session may hold.
- Most subscription cards show `access unknown` until the records carry their licences or the entitlement adapter is asked per card.
- Teaser quality and cross-language ranking seen on the live index ("Was ist neu?" as a DMW teaser, a defibrillation article first for an atrial fibrillation query filtered to DMW) are search-tuning work for SM-08.
