# 0031 Auth, rate limits, metering and telemetry

- Status: accepted; auth (decision 1, API keys, OAuth) superseded by [0048](0048-public-server-without-auth.md)
- Date: 2026-11-03
- Amends: ADR 0025 (decision 1, loopback-only HTTP; decision 5, the local caller)
- For: ticket SM-10, PLAN.md "Security and privacy", "Edge cases and failure handling"

## Context

The plan asks for API keys stored hashed and identified by prefix, OAuth 2.1 resource-server mode, a per-key token bucket, `Origin` checks with CORS closed, body and query limits, `/healthz`, `/readyz`, `/metrics`, OpenTelemetry traces, a metering outbox exported as JSON lines and to a webhook with backoff, and a SIGTERM that drains requests and flushes the outbox. It leaves open the key format, where keys live, where the rate limit applies, how the outbox is delivered when one of two sinks fails, which metrics carry which labels, and what probes may reach. Facts found while building it:

- SDK 2.4 verifies bearer tokens (`verifyBearerToken`), builds the `401`/`403` challenge, and passes a verified `AuthInfo` to the server factory per request. It does no verification of its own, and `toNodeHandler` cannot pass `AuthInfo`, so the app wraps the MCP handler in its own web-standard handler.
- A web `Request` drops the `Host` header; the Node adapter puts it in the URL instead, and Node refuses HTTP/1.1 requests without `Host`.
- `verifyBearerToken` rejects any `AuthInfo` without `expiresAt`.
- `prom-client` is deprecated in favour of `@prometheus-io/client` (same API). `@opentelemetry/sdk-trace-node` is deprecated in favour of `@opentelemetry/sdk-trace` 3.0, whose packages need `@opentelemetry/api` 1.10.

## Decision

1. **Auth modes.** `AUTH_MODE` is `none`, `api-key` or `oauth` (`api-key+oauth` added by [ADR 0047](0047-api-keys-and-oauth-in-one-deployment.md)). `none` gives every request the local caller and is refused by config when HTTP binds beyond loopback. Stdio always has the local caller. Every mode reads `Authorization: Bearer …` only.
2. **API keys.** A key is `smk_<id>_<secret>`: the id is `key_` plus 12 base32 characters (60 bits), the secret 32 random bytes as base64url. The id is the prefix the plan asks for: it names the caller in logs, landing sessions and usage events, and finds the row. Only the SHA-256 of the secret is stored, in the runtime database's new `api_keys` table, and compared in constant time. A fast hash is enough because the secret has 256 bits; a password hash would only slow every request. `scholarly-mcp keys create --label … [--institution …]`, `keys list` and `keys revoke <id>` manage them; the key is printed once. A key may carry an institution id, which reaches `Entitlements`.
3. **Seconds-only auth cache.** Accepted and refused decisions are cached by the key's hash for `AUTH_CACHE_MS` (5 s, at most 60 s), so a revoked key stops within that time and a flood of bad keys does not reach the store. A store failure answers `500 server_error` and is not cached. Accepted keys get a nominal one-hour `expiresAt` for the SDK.
4. **OAuth resource-server mode.** JWT access tokens are checked with `jose` against `OAUTH_JWKS_URL`: signature (asymmetric algorithms only, no `none`), `OAUTH_ISSUER`, `OAUTH_AUDIENCE` (this server's `/mcp` URL, RFC 8707) and `exp`, with 30 s clock tolerance. `OAUTH_REQUIRED_SCOPES` answers `403 insufficient_scope`. The caller is `oauth:<client_id | azp | sub>`, optionally with an institution from `OAUTH_INSTITUTION_CLAIM`. The token is never passed upstream. A key set that cannot be fetched is a server error, not the client's. The server publishes RFC 9728 Protected Resource Metadata at `/.well-known/oauth-protected-resource/mcp` and names it in each challenge, so MCP clients find the identity provider. JWTs cannot be revoked here; short token lifetimes at the identity provider cover that.
5. **HTTP layer.** One web-standard handler routes everything. `/mcp` checks `Host` against `HTTP_ALLOWED_HOSTS` (from the URL, see the facts above) and a present `Origin` against `HTTP_ALLOWED_ORIGINS` (both hostname lists, localhost by default), then authenticates. Config requires `HTTP_ALLOWED_HOSTS` and an auth mode when HTTP binds beyond loopback. `/healthz`, `/readyz` and `/metrics` skip those checks, since probes and scrapers reach the pod by address, and they hold no article data. No route sends CORS headers. Limits: URL 2 KB (`414`), headers 16 KB (`431`), body 64 KB (`413`), 10 s to send headers, 60 s per request.
6. **Rate limit per tool call.** Each caller has an in-memory token bucket (`RATE_LIMIT_PER_MINUTE`, default 60, bursts of `RATE_LIMIT_BURST`, default 20). Every tool call takes a token before its input is parsed; an empty bucket is the tool error `RATE_LIMITED` with `retryAfter` in whole seconds, as the plan's error table has it. Handshakes and tool lists cost nothing. Several processes each allow the full rate; a shared limit needs a shared store and waits for a deployment that has more than one process. Full buckets are swept when more than 10,000 callers are tracked.
7. **Metering outbox.** Every tool call, failed or not, records one usage event: a fresh UUID as the idempotency key, key id, tool, result count, latency, status (`ok`, an error code, or `INTERNAL`) and `billable` (only `ok`). No query text. `record` starts an insert into `usage_events` and returns; a failed insert is logged and counted, never thrown. The exporter runs every `METER_EXPORT_MS` (5 s). It sends batches of `METER_BATCH_SIZE` (500) to every sink and marks a batch exported only when all sinks took it, so delivery is at least once and receivers dedupe on `id`. Failures back off exponentially with full jitter, never below the interval and up to `METER_BACKOFF_MAX_MS` (5 min). Passes never overlap. Exported events are deleted after `METER_RETENTION_DAYS` (30); pending events are never deleted.
8. **Sinks.** JSON lines are always written, to `METER_JSONL_PATH` (`data/usage.jsonl`), so events never pile up unexported by default. With `METER_WEBHOOK_URL` set, batches are also POSTed as `{ "events": [...] }`. The request carries `Idempotency-Key` (a hash of the batch's ids) and `x-scholarly-timestamp`. With `METER_WEBHOOK_SECRET` (32+ characters), it also carries `x-scholarly-signature: sha256=<HMAC-SHA256 of "<timestamp>.<body>">`. Any 2xx accepts the batch. Redirects are refused.
9. **Metrics.** A Prometheus registry per app, with Node defaults plus tool calls by tool and status, tool duration, HTTP requests by fixed route label and status, auth failures by OAuth error code, events exported, export failures, dropped events, outbox depth, index readiness and requests in flight. No label carries a key id or query text: key ids would show who uses the server and grow without bound.
10. **Traces.** Set `OTEL_EXPORTER_OTLP_ENDPOINT` and the server registers a tracer provider with the OTLP HTTP exporter (which reads the other standard `OTEL_*` variables) and an AsyncLocalStorage context manager. A server span covers each HTTP request; a child span covers each tool call with tool name, status and result count. Without the variable, the API stays a no-op.
11. **Readiness and shutdown.** `/readyz` is ready when the index is open, the model is loaded and the server is not draining. The model loads before the server listens, so it is always loaded once `/readyz` answers. On SIGTERM the server stops its timers, turns readiness off, stops accepting connections, asks clients to close their connections and waits up to `SHUTDOWN_TIMEOUT_MS` (10 s) for requests in flight. Then it cuts the rest, stops the exporter, waits for outbox writes and runs one more export (5 s budget), flushes spans and closes the files. Events the last export cannot send stay in the outbox for the next start.

## Consequences

- The loopback-only rule of ADR 0025 is replaced by the allowlists plus an auth mode. A public deployment needs TLS at the load balancer (PLAN.md) and should keep `/metrics` internal there.
- `LOCAL_CALLER` lives in `auth/auth-info.ts` and is now only the caller of stdio and of `AUTH_MODE=none`.
- `UsageEvent.status` gains `INTERNAL`; the runtime database gains migration 2 (`api_keys`, an index on exported events). Core gains the `ApiKeyStore` and `UsageOutbox` ports, with testkit fakes and contracts that the SQLite adapters pass.
- Billing receives each event at least once and must dedupe on `id`; the JSON-lines file can repeat a batch when the webhook failed after it.
- The rate limit is per process. Moving to several replicas needs a shared bucket store (a new port), noted for SM-13/SM-14. Done in ADR 0036: with `STORE=postgres` the buckets are shared.
- Exit check: every server and metering edge case named in the ticket has a test. A live smoke test on the real index served `401` without a key, searched with a key (5 cards, 349 ms), exported both events to JSON lines within a second and stopped cleanly on SIGTERM, with no query text in logs or events.
